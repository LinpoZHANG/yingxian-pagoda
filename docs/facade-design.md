## 一、这套系统管什么、不管什么

### 1.1 一句话

「古今面貌」换的是**立面上的三样东西**:墙体、开口、面层。承重与形制不动。

### 1.2 边界(不可越界)

| | 古今之间 | 处理 |
|---|---|---|
| 柱、阑额、普拍枋、铺作、屋面、平座勾阑、台基、塔刹 | **无可考的形态变化** | 几何一律不碰;只有**面层颜色**可随年代变 |
| 首层 | 两个年代都记「相对封闭」,拆墙工程只及二至五层明层 | 几何不动,面层随年代变 |
| 二至五层明层次间 / 当心间 | 墙体与开口都变 | 本系统的主战场 |

依据:资料包时间线未记任何主体结构改动;`ERA_LEVELS = [2,3,4,5]`。

### 1.3 对既有代码的侵入(全部是纯附加)

| 文件 | 加了什么 | 为什么不算破坏 |
|---|---|---|
| `components/wall.js` | 墙片与窗挂 `userData.{face, bay}`,窗另挂 `{sill, head}` | 语义标记,不进几何、不进渲染 |
| `materials/studyMode.js` | `registerStudyMaterial()` 登记口 | 子系统的独占材质自报族色,名册仍在 materials/ |
| `interaction/picking.js` | 可见性判到祖先链;实例高亮在基色之上再乘 | 修的是既有缺陷 |
| `interaction/states.js` | `era` 字段,与 `mode` 正交 | 无互斥,不改任何迁移 |
| `main.js` | 调 `createFacadeHistory` 与 `applyBracketTones`;剖面壳跟随本体显隐 | 接线 |

古貌构件挂在**各明层的 storey 组**之下,所以分解、逐层、巡航、剖透视的一切变换自动跟随,
不占 `explode.js` / `cameraRig.js` 一行。

## 二、材质分组(色系谱系)

全塔外露面分成 **六族**(五族今貌 + 檐下油饰面),另有古貌专属两族。族与族之间靠 **G/R、B/R 两个比值**拉开——
比值管「多红」,亮度管「多深」,两者要分开调(见 §四)。

### 2.1 谱系总表

| 族 | 用在哪 | base(线性) | G/R | B/R | 性格 |
|---|---|---|---|---|---|
| **裸木·柱枋** `WOOD.pillar` | 内槽柱、暗层柱、副阶柱、梁栿 | `[0.216, 0.184, 0.170]` | 0.852 | 0.787 | 千年氧化的灰调褐 |
| **裸木·斗栱** `WOOD.bracket` | 全塔铺作(顶点色再分斗/栱/昂/枋) | `[0.250, 0.213, 0.198]` | 0.852 | 0.792 | 檐下遮蔽,留住油色,最偏木色 |
| **薄料细工** `TRIM_COAT` | 勾阑(望柱/寻杖/盆唇/华板)、明层格扇 | `[0.246, 0.220, 0.212]` | 0.894 | 0.862 | 全暴露、褪得净、返灰 |
| **油饰红·塔身** `COLUMN_COAT` / `plankBases` | 明层外槽柱、外槽阑额普拍枋、窗上下余壁 | 见 §2.3 | 0.672–0.779 | 0.582–0.702 | 木面刷红,几十年不重刷 |
| **油饰红·一层** `MODERN_RED_WALL` | 首层厚墙 | `color 0xb87a6c` 乘砖贴图 | — | — | 抹灰砖墙,檐下少晒、重刷最勤 |
| **檐下油饰面** `MODERN_COAT` | 栱眼壁(外槽/内槽/平座/副阶)、板门门颊 | `[0.196, 0.166, 0.152]` | 0.847 | 0.776 | 全塔**最暗**的一族 —— 它是斗栱的背景板 |

另有**古貌专属**两族:夹泥墙抹灰(§2.5)与古貌柱枋土色(§2.4)。

**檐下油饰面为什么单列**:栱眼壁退在泥道栱之后、终日不受直射,是铺作带里最暗的一层,
斗栱正是靠它当背景才跳得出来。它的比值与裸木族接近(同是褪色木面),
**分野在明度** —— R 0.196,低于斗栱的 0.250。这条是硬约束,见 §2.6 第 2 条。

### 2.2 为什么这么分

分族的依据是**做法 + 境遇**,不是好看:

- **斗栱 vs 勾阑格扇** —— 前者退在檐下、终日遮蔽,后者是外露的薄料细工、风雨直吹。
  资料包 §2 记斗栱「檐下偏暗,端部及朝阳面褪色」。故薄料族比斗栱**亮一档、灰一档**
  (G/R 0.894 : 0.852)。差半档到一档:够读出「这是两类构件」,又不至于看成两种木头。
- **塔身红 vs 一层红** —— 一层墙退在副阶檐下少受直晒,又是礼仪面、重刷得最勤;
  塔身二至五层全无遮挡、几十年不重刷。故**塔身必须更淡**(§2.6)。
- **刷漆面 vs 裸木** —— 版壁是木板上刷红涂料,勾阑斗栱是裸露旧木。
  同亮度下前者偏红半档以上。

### 2.3 油饰红·塔身的三个取值

```
柱 / 外槽阑额普拍枋   COLUMN_COAT.base   [0.258, 0.176, 0.152]   G/R 0.682  B/R 0.589
版壁·漆重             plankBases[0]      [0.268, 0.180, 0.156]   G/R 0.672  B/R 0.582
版壁·漆薄             plankBases[1]      [0.262, 0.204, 0.184]   G/R 0.779  B/R 0.702
```

版壁做**两套 base 而不是一套**:这面墙的底子是红,木色是漆刷得薄、磨掉的地方露出来的那一层。
「漆重」是涂料完好的板,「漆薄」是磨出木色的板。两套都仍明显红于裸木族,
所以整面墙的**基调是红的**,板与板的差别读作「这块漆还在、那块磨出了木色」,
而不是「这块木头深一点」。

### 2.4 古貌柱枋:赭土色

```
COLUMN_ANCIENT.base  [0.268, 0.209, 0.166]
```

拆改前的立面是**夹泥墙 + 木构**的复合面。墙是温灰白到浅土色,木构若是一遍鲜红,
整面就成红白硬碰。资料包 §3.1 对辽代状态的措辞是「木构**可能**具有赭红或朱红系油饰,
但不宜使用现代高饱和大红」——「可能」二字本就没给红一个确定的位置。

故古貌取赭土色:与夹泥墙同一暖色系、明度低一档,读作「同一片墙上的木骨」,
而不是「白墙上钉了红条」。**接近但不相同**是这条的分寸——完全一样会把柱子融进墙里,
立面的骨架就散了。今貌那遍红是有照片的,留给今貌。

### 2.5 夹泥墙(古貌)

```
thickness      WALL.thickness * 1.28 = 0.435 m   比木版壁厚 —— 泥墙是有体量的填充
frameRatio     0.26      木骨(上下槛/腰串/立颊)断面 / 墙厚
plasterRecess  0.05 m    抹灰面自木骨外皮退入 —— 框凸墙凹,侧光才有分界
columnClear    0.30 m    墙端让柱,避免与柱身穿插(资料包 §6.7)
brace          { w:11, h:15 } 分°   墙内斜撑断面
plasterTones   [0xe0d7c0, 0xd9ceb2, 0xe6dcc7, 0xd2c6a9]   四档逐间轮换
```

**做法约束**(资料包 §6):不得做成现代水泥板/石膏板/全平纯白墙;墙体不得与柱梁斗栱穿插;
历史转变不能只做色相切换。故墙是「木骨 + 填泥抹灰」,抹灰填在木骨围出的格里,
与任何框料**都不重叠**(不重叠还有一层技术原因,见 §五·3)。

### 2.6 必须守住的三条关系

改任何一族之前先看这三条。它们是**关系**,不是数值——数值可以重调,关系不能破。

| # | 关系 | 出图实测判据 |
|---|---|---|
| 1 | 一层朱红墙 > 塔身刷漆面 > 裸木 | 饱和度 S **0.369 / 0.22–0.24 / 0.25 左右**,一层与塔身约差 **1.6 倍** |
| 2 | 栱眼壁必须**暗于**斗栱 | `MODERN_COAT.base` R **0.196** < bracket R **0.250** |
| 3 | 薄料细工比斗栱亮一档灰一档 | G/R **0.894** : 0.852 |

- 第 1 条破了:「红墙」和「刷漆面」都读不出来,整片红糊成一块。
- 第 2 条破了:栱眼壁跳到斗栱前面,整条铺作带糊成一片,**数不出跳数**——
  那是第35轮立过的底线。
- ★ 第 1 条的「淡」落在**饱和度**上,不是压暗。三者明度基本持平(0.33 / 0.33 / 0.36);
  靠压暗做会让塔身显脏,还会跟本来就暗的斗栱糊在一起。

## 三、逐件色差机制

同一族里,件与件之间还要有差别,否则一圈四十八朵、一道墙十块板都是同一个色号,
远看是一条均匀的带子,近看像同一个模型复制了几百遍。

### 3.1 三种粒度

| 对象 | 粒度 | 机制 | 参数 |
|---|---|---|---|
| 铺作 | 逐朵(520 朵) | `InstancedMesh.setColorAt` 逐实例色 | §3.2 |
| 版壁 / 余壁 | 逐块板 | 六种材质(2 base × 3 明度乘子) | `plankTints` |
| 勾阑 / 格扇 | 逐件 / 整扇 | 九种材质(3 木纹 seed × 3 明度乘子) | `TRIM_COAT.seeds/tints` |
| 立面柱 | 逐柱 | 逐实例色 | `COLUMN_COAT.jitter = 0.040` |

### 3.2 铺作:两条轴 + 斑块

```
LIGHT    0.072   明暗轴:用料本身的深浅(三通道同加)
WEATHER  0.064   风化轴:动 R 与 B 的平衡,偏暖 ⇄ 返灰,不动整体明度
                 r -= w*0.55 ; g += w*0.30 ; b += w*0.55
PATCH    0.55    斑块占比,其余 0.45 为逐朵抖动
PATCH_XZ 4.5 / PATCH_Y 4.0   斑块尺度(m),三维值噪声,按**世界坐标**采样
SUN { r:0.0055, g:0.011, b:0.013 }   朝阳面褪色,按面序余弦
```

两条轴**各取一次哈希**(`salt` 分开),同一朵的明暗与风化不该同涨同落。

**斑块**的道理:真实的补配是**成片**换的,一次工程换掉一段檐,相邻几朵常出自同一批料。
这一项让色差有「片」的形状,而不是逐朵互不相干的椒盐噪点。
0.55 是「看得出成片、又看得出片内每根不同」的分界。

**朝阳面**:资料包 §2「端部及朝阳面褪色」。面序 0 = 正南,按 `cos(face × 45°)` 给,
南面褪得亮而灰、北面留住油色偏暗偏红。褪色不是单纯提亮,G/B 提得比 R 多。
这是**平缓的梯度**,不是周期花纹,故可以保留(对照 §五·1)。

出图实测:朵型解释掉的色调方差 **2.5%**;相邻朵对明度差 **2.89%**、色调差 **2.47%**。

### 3.3 定值,不用随机数

所有逐件色差都由 `(层·面·序号·位置)` 经 murmur3 finalizer 混合定值。
**不用 `Math.random()`** —— 一块木板的深浅是它自己的属性,不该每次刷新换一张脸。

### 4.1 差异总表

| | 古貌 `survey_1933` | 今貌 `current_2017_plus` |
|---|---|---|
| 次间 | 夹泥墙(木骨分格填泥抹灰) | 连续格扇 + 窗上下余壁(刷红木板) |

| 斜向四面当心间 | **封死** | 通间格扇 |
| 东西正向当心间 | 一扇**小窗**(宽 0.56 间、高 0.62 洞带、五棂) | 通间格扇 |
| 南北当心间 | 板门(两代同在) | 板门 |

### 4.2 开口规则的依据

```
ANCIENT_OPENING.cardinalFaces = [0, 2, 4, 6]    // 0 = 南,逆时针;即南东北西四正向
                widthRatio    = 0.56            // 古貌窗宽 / 当心间宽
                heightRatio   = 0.62            // 古貌窗高 / 今貌窗洞带高
                lattice       = 5               // 古貌棂少而粗;今貌是方格心
```

两处彼此印证:README §3.1「二至五层每个明层只有东、西、南、北四个正向设置主要门或开口;
其他开间较封闭」;timeline `pre_alteration_1927.facade_openness = "lower_than_current"`,
而 `post_alteration_1936` 才转为 `continuous_lattice_screens: true` / `facade_openness: "high"`。

窗洞的上下皮**不另拍标高**,直接自今貌那扇窗的 `userData.{sill, head}` 上读——
两个年代的开口因此落在同一条带里,换的是这条带里填什么。

### 4.3 证据等级

| 内容 | 等级 |
|---|---|

## 五、三条已经付过学费的禁区

写在最前面,因为每一条都是出图之后才发现的。

### 1. 不要按「构件类型」给系统偏置

曾按朵型给铺作偏置(转角风化最重、补间最轻),道理站得住,做出来是灾难:
**每一面的朵型序列完全一样**(转角·补间·柱头·补间·柱头·补间·转角),
八个面、十二圈重复同一段节奏,解释掉 **22%** 的色调方差,一眼读成花纹。

> **判据:凡「按构件类型给系统偏置」,先问这个类型在立面上是不是周期出现的。**
> 想表达「转角风化更重」这类道理,得让它跟着**位置**走(如朝阳面那条余弦梯度),
> 不能跟着**类型**走——类型在立面上是按柱网周期排布的,而柱网本身就是一段重复的节奏。

### 2. 哈希的输入与取模

- **模数与输入的公因子要先用雪崩打散。** 曾用「各乘大质数再异或 + 右移」,
  `板序 × 奇数` 的奇偶性直接透到 `% 6` 上,出来是 `A B A B` 的横道。
  一律用 murmur3 finalizer 逐级混合。
- **按位置定值前,先确认取的那个对象真的带坐标。** `latticeWindow` 返回的组
  自身停在原点(子网格才带世界坐标),拿组的 `position` 去哈希,**整层的窗算出同一个色**。
  组、Object3D 容器、InstancedMesh 的父节点都常常停在原点。
- **斑块噪声用值噪声,不要正弦叠加**:正弦在圆环上必然生出周期,而这里要躲的正是周期。
  且必须按**世界坐标**采样——用实例局部坐标,各层各自从零起算,层与层会采到同一片斑块。

### 3. 长焦远景下,「藏在里面」是藏不住的

立面机位在约 480 m 外,渲染器 `near = 0.05`、`far = 67.31 × 200`,该处深度分辨率约

```
Δz ≈ z² / (near · 2ⁿ) = 478² / (0.05 × 2²⁴) ≈ 0.27 m
```

9 cm 的前后关系在那里分不出来。所以:

- 墙内斜撑**不能**靠「被抹灰盖住」来隐藏——它是一段两端归零的脉冲,古貌静止态根本不画;
- 夹泥墙的抹灰**填在木骨围出的格里、与框料不重叠**,前后关系不交给深度缓冲仲裁;
- 被完全包住的构件**不该有投影权**(影子会穿到包住它的那个面的正面上)。

## 六、变化动画

### 6.1 相位表

`t`:0 = 古貌,1 = 今貌。总时长 `ERA_TRANSITION = 2.0 s`。反向播放即同一条曲线倒着走。

| 相 | 区间 | 管什么 |
|---|---|---|
| `plaster` | [0.00, 0.42] | 夹泥墙抹灰退 |
| `frame` | [0.12, 0.58] | 木骨与古貌小窗棂随后 |
| `braceIn` | [0.30, 0.44] | 抹灰退尽,**墙内斜撑显露** |
| `braceOut` | [0.58, 0.72] | 斜撑随木骨一并拆除 |
| `coat` | [0.28, 0.80] | 面层:抹灰 ⇄ 油饰,整程渐变遮罩 |
| `modern` | [0.70, 1.00] | 版壁与格扇接手 |

斜撑是**脉冲**,两端归零:`smoothstep(braceIn) × (1 − smoothstep(braceOut))`。
古貌静止态它藏在墙里本就看不见,今貌已拆除更不该在;只在「抹灰已退、版壁未到」那一段现身——
这是资料包 §5 要的那句话在模型里唯一能被看见的形式:**拆的不只是饰面,墙里那套抗侧刚度也一并没了**。

### 6.2 两种切换手段,各管一类

| 手段 | 用在哪 | 为什么 |
|---|---|---|
| **不透明度淡化** | 只属一个年代的构件:夹泥墙、木骨、斜撑、古貌小窗、格扇、版壁 | 这些构件在另一个年代**不存在**,该整块淡出 |
| **渐变遮罩(叠副本)** | 两个年代都存在、只换面层的:栱眼壁、门颊、余壁、一层墙、**立面柱与阑额** | 一个网格只能挂一份材质,换材质就是跳变 |

**遮罩的做法**:给每个面加一片**同几何的兄弟副本**,挂今貌材质、`polygonOffset` 拉向相机一侧,
让副本的不透明度 0 → 1 渐显。两个细节决定它成不成立:

- **底下那片古貌的面始终不透明。** 若两片各取 50% 交叉淡化,过渡中整座塔会变成半透明的壳——
  栱眼壁一透,檐下就能一穿到底,那正是 `gongyanbi.js` 存在的理由。只让上面那片渐显,覆盖率恒为 1。
- **静止态只画一片。** 副本不透明时把本体 `visible` 关掉,古貌时把副本关掉。
  绘制批次与不做遮罩时一样,只有过渡中的两秒是双份。

副本另有两处要打招呼:**棱线层**与**剖透视断口**都按 `userData.eraOverlay` 跳过它,
不然同一条棱会出两份线、同一个断口会做两份盖子。

### 6.3 一条借材质的规矩

> **凡跨模块借材质,借的一方要么独占克隆,要么明说不参与过渡。**

踩过两次:

- 明层格扇改挂全塔共享的 `WOOD.trim` 之后,它就自动退出了淡入淡出(共享材质不能调不透明度,
  会拖走板门与勾阑)。
- 反过来,勾阑与格扇同色,但必须做**两套同色的材质**(`TRIM_TONES` / `MODERN_TRIMS`):
  勾阑两个年代都在、永不淡化,格扇只属今貌。共用一套的话,古今切换会把全塔勾阑一起拖淡。

### 6.4 动画的定性

这段过渡在文档与代码注释里一律标注为**「历史结构解释动画」**,
不声称真实维修按此顺序发生。年份一律写「1934—1935 年间」——
公开资料在 1934 与 1935 之间有分歧,不伪造精确到日的施工时间。

## 六附、夜景内透(依赖立面开口)

夜景此前只有 `lighting.js` 的**二十四盏檐下点光**,坐在 `eaveW/2 × 0.82` 的半径上 ——
全在塔身外面,照的是檐口与瓦面。入夜后塔身是一具从外面打亮的壳子:
五个明层的佛堂漆黑,满立面的格扇读成一片黑格子。

`scene/nightInterior.js` 给每个明层的**内槽**放一盏佛堂灯(共五盏),做出内透。

### 为什么不用开阴影就不漏光

直觉上「室内点光会把外墙也照亮」,实际不会 —— **朗伯项自己会挡**:

| 面 | 法线 | 室内灯的 L | `N·L` | 结果 |
|---|---|---|---|---|
| 外墙外皮、棂条外侧、瓦面 | 朝外 | 朝内 | **< 0** | 拿到 0,不受影响 |
| 外墙内皮、内槽柱、佛像 | 朝内 | 朝内 | > 0 | 受光 —— 正是透过格眼看见的那些 |
| 上层楼板上表面 | 朝上 | 自下而上 | < 0 | 不串层 |
| 本层天花(上层楼板下表面) | 朝下 | 自下而上 | > 0 | 受光,正确 |

点光的立方体阴影要渲六个面,五盏就是三十次 —— 在 145 万三角形上不可接受。
**靠法线方向拿到同样的结果,是这套做法唯一能成立的理由。**

### 参数

```
color        0xff9a48    比檐下灯笼(0xffb865)更暖更红 —— 檐下挂纸灯笼,堂内点油灯与烛
heightRatio  0.45        灯位 / 明层柱高,约当佛坛上方供桌灯烛
reachRatio   1.55        有效半径 / 该层角柱半径,越过外槽柱、在平座勾阑前衰减掉
decay        2.0         物理衰减
intensity    30.0        内槽柱(6~7 m)约 0.8,外墙(11 m)约 0.25 —— 内亮外暗
groundFloorScale 0.55    首层砖墙 + 板门几乎不透光,给足了反而糊
```

另有**格扇自发光**补一层:单靠室内灯,格眼里看见的是被照亮的内槽 —— 那是对的,
但棂条本身逆光全黑,远景里一扇格扇会退成一块黑斑。棂条是薄木条,背后有光时
边缘本就透出一层暖晕,故给 `emissiveIntensity 0.34`(色 `0xff8a3c`,昼态恒为 0)。
按 `partKey === 'window'` 认材质 —— 板门(实木不透光)与勾阑(不属窗)都不在其内;
古貌那几扇小窗也挂了同一个标记,故两个年代都透光。共十份材质(今貌 9 + 古貌 1)。

灯挂在**各层 storey 组**之下,故结构分解时随本层升起 ——
挂到场景根上的话,分解一开五盏灯会全留在原地照进空气里。

### 试过又撤掉的:地面射灯

用户第59轮「看不清屋檐瓦面,应该增加一些射灯」,第60轮改为「去掉射灯,增加月光」。
两轮都记下来,因为撤掉的理由本身就是这一块的关键约束:

> **任何位于屋面下方的光都照不亮瓦面。**
> 与内透那条是同一个朗伯项,只是方向反过来:瓦面法线朝上外,地灯入射朝下内。
> 设屋面坡角 θ、射灯俯角 φ,则 `N·L = sin(θ − φ)`,只有 θ > φ 才受光。
> 本塔屋面坡角约 28°,而自 30 m 外的地面看 30 m 高处俯角已有 42° —— 照不到。
> 往外挪俯角虽小但距离更远、照度掉得更快;往里挪就被副阶檐(滴水线 18.2 m)挡住。**两头都堵死。**

射灯真正能照到的只有檐下与檐口(朝下、朝外的面)—— 而那一带**檐下灯笼已经在做**。
八盏灯换来一层与既有光源重叠的补光,不值它的着色器代价,故撤。

**「看不清瓦面」的正解是抬月光**:`NIGHT.sunIntensity` 0.95 → 1.45 → **2.10**。

撤光源时要问的是「它原本在补什么」,而不是只把主光调亮 ——
射灯此前还在给塔身**背月一侧**的外墙与柱子补光,月光是有向的,补不了那一侧。
故天光与环境光同时抬一档(`hemiIntensity` 0.50 → 0.62、`ambientIntensity` 0.30 → 0.34),
否则背光面会掉进死黑。

**灯数账**:檐下 24(旧)+ 佛堂 5 = **29 盏点光 + 1 盏平行光**。
前向渲染下每个材质的着色器都要遍历全部灯,这已是这套场景该有的上限 ——
再要加光源,应先问能不能用现有的哪一组去兼("一盏灯 + 平缓衰减近似一片灯"就是这个思路),
而不是继续往上堆。第59轮那八盏射灯正是没先问这一句。

### 「针对塔身加亮」:先问哪组光源的作用域与它重合

用户第61轮「月光还不够亮**针对塔身**」。这个限定要当真 ——
**瓦面与塔身暗得不是同一个原因,因而不归同一盏灯管**:

| | 为什么暗 | 归谁管 |
|---|---|---|
| 瓦面 | 朝上的面,月光(高度角 51°)直给 `N·L ≈ 0.82` | 月光,抬了立竿见影 |
| 塔身 | **竖直面** `N·L ≤ 0.63`,且只有朝月那几面拿得到;斗栱带整条**退在檐影里**,有向光根本进不去 | 见下 |

塔身的三盏候选,只有一盏是**只照塔、不照城**的:

| 光源 | 作用域 | 用它加亮塔身的后果 |
|---|---|---|
| 月光(有向) | 全场 | 推到 3.2 也只是让瓦面过曝,檐影里照样不亮 |
| 天光 / 环境光(无向) | 全场 | 进得去檐影,但**同时点亮城郭与地面** —— 抬到够用,整张图成了黄昏 |
| **檐下灯笼**(点光) | 半径 `eaveW × 0.85`,约 22 m | 出了塔就衰减殆尽,城郭一点拿不到 ✔ |

> **判据:「针对某个物体加亮」要先问哪一组光源的作用域与那个物体重合。**
> 不问这一句,就会在全局光上反复加码,把整张图一起推亮而目标物依旧不突出。

灯笼同时要**改衰减形状**,不能只加强度:它坐在檐下 0.9 m,取平方衰减时
贴着灯的那片椽底是 6 m 外斗栱带的 **47 倍** —— 抬强度只会先把灯下那一小片烧白。
压到 `decay 1.45`、半径 ×0.55 → ×0.85 后这个比降到 **16**,灯下几乎没变(1.235 → 1.165)
而斗栱带涨到 2.8 倍;再乘强度 17 → 30,斗栱带合计约 **5 倍**。

**夜景四值(第61轮)**:

```
sunIntensity     0.95 → 1.45 → 2.10 → 2.60 → 3.20   月光,管瓦面
hemiIntensity    0.50 → 0.62 → 0.95 → 1.10          天光,进得去檐影但也照城
ambientIntensity 0.30 → 0.34 → 0.52 → 0.58
lanternIntensity 11.0 → 17.0 → 30.0                 檐下灯笼,唯一只照塔的一组
lantern decay/半径  2.0 / ×0.55  →  1.45 / ×0.85
```

实测(同机位,塔区 vs 城郭亮度中位):

| | 塔区 | 城郭 | 塔/城 |
|---|---|---|---|
| 改前 | 0.051 | 0.118 | 0.43 —— **塔比城还暗**,只能读成剪影 |
| 中途(只抬月光与天光) | 0.071 | 0.147 | 0.48 |
| 现在 | **0.159** | 0.176 | **0.90** |

塔区涨 3.1 倍,城郭只涨 1.5 倍 —— 定向性就落在这个差上。

### 「加亮某一盏」时,先看它占总照度的几成

用户第62轮「增加室内灯源的亮度」。第一次只把 `intensity` 12 → 13 并压平衰减,
出图实测整塔中位只从 0.1588 动到 0.1608 —— **几乎没有变化**。

原因不在管线,在**份额**:那些表面上的照度是室内灯 + 檐下灯笼 + 天光 + 环境光四者之和,
而檐下灯笼刚在上一轮抬到 30。室内灯当时只占约四分之一,把它翻倍只让总量 +25%,
经 ACES 压缩后落到画面上就剩几个百分点。

> **判据:给一个只占小份额的分量加倍,是看不出来的。**
> 要动就得动到它足以主导 —— 先算这盏灯在目标表面上占几成,再决定倍数。

改到 40 之后(内槽处 6.04,而檐下灯笼在同一处只有 2.21),受影响的那 7.2% 像素
自 L 0.210 升到 0.262(**×1.25**),增量 RGB (+21, +12, +6) 明显偏暖。

**另一条教训:取样框要先叠在图上看一眼。** 前两次量出「几乎没变」,
一部分也是因为取样框跨在勾阑与檐下上,真正的格扇与内透只占框内一小块,
把变化稀释掉了。把框画到图上一看就清楚了。

### 调这一块时的两个旋钮

| 现象 | 拧哪个 |
|---|---|
| 当心间一团死白、次间格扇发黑 | `decay` —— 取物理的 2.0 时内外差 3.4 倍,压到 1.4 配合放大的 `reachRatio`,内外比落到 2.5 |
| 平座那圈比格扇还亮 | `heightRatio` —— 灯抬高则楼板 `N·L` 变大、地面抢戏;压低则光走得更平,竖直面(格扇、内墙)拿得多 |
| 瓦面还是黑 | 只能抬 `NIGHT.sunIntensity` —— 屋面下方的任何光都照不到它 |
| **塔身**不亮 | `lanternIntensity` + 灯笼的 `decay`/半径 —— 全局光会把城一起点亮,只有它是塔局部的 |
| 灯下一小片烧白、远处仍暗 | 灯笼的 `decay`,不是 `intensity` —— 先改衰减形状再谈强度 |

`decay` 与 `intensity` **必须成对调**:指数变了,同一个强度值的含义完全不同。

### 与年代的关系

这盏灯不分年代,但**看见的结果分**:

- **今貌** 满立面连续格扇,一整圈都透光;
- **古貌** 次间是夹泥墙、斜向四面当心间封死,只有四正向那几扇小窗漏出光来。

「由封闭转为玲珑通透」这句话,在夜里比白天更容易读出来。
所以改 §4.1 的开口规则时,记得它同时改变的还有夜景。

## 七、与其他系统的接口

| 系统 | 接口 | 注意 |
|---|---|---|
| 构造读图模式 `L` | 每个独占材质都要 `registerStudyMaterial(mat, 族色)` | 不登记的话按 L 后整塔平色里空一块 |
| 构件拾取 | 可见性判到**祖先链**;实例高亮在基色之上**再乘一道**,撤销还原到接手时的值 | 硬编还原成白会抹平逐朵色差 |
| 剖透视断口 | 副本记住本体、跟随其整条祖先链的可见性;年代落位后重刷一次 | 不跟的话,拆掉的墙会在剖面里留鬼影 |
| 棱线层 | 按 `userData.eraOverlay` 跳过遮罩副本 | 同一条棱只出一份线 |
| 结构分解 / 逐层 / 巡航 | **无接口** —— 古貌构件挂在 storey 组下,变换自动跟随 | 不占 `explode.js` / `cameraRig.js` |

> **通道规矩:凡把某个通道当「临时画布」用(instanceColor / userData 缓存 / 材质替换),
> 撤销都必须还原到「接手时的值」,不能还原到某个假定的初值。**
> 一旦有第二个系统也用这个通道,硬编的初值就会悄悄吃掉它。

## 八、调参手册

### 8.1 逐通道反推,不要按材质端的 S 定

场景是暖色阳光,**蓝分量在光源端本就被压着**,材质端加的蓝进不到画面里。
曾把 base 的 S 从 0.27 压到 0.18,出图的 S 只从 0.33 动到 0.32。

按「出图目标 → 除以各通道的光照系数 → 材质端取值」反推,实测系数:

```
R ≈ 431    G ≈ 401    B ≈ 340
```

### 8.2 三个轴分开量

明度、饱和度、色相是**三件事**。在一条轴上加幅度,补不了另一条轴上的零。
定值时把渲染图与实照都转到 HLS 逐项对,每轮才能确定这次错的是哪一个——
凭感觉调,很容易在纠正一个轴的时候把另一个推出去。

### 8.3 判据是「与既有木构比」,不是与照片的绝对值比

全塔在 ACES 下整体比实照饱和一档:未改动的 `WOOD.pillar` 出图也有 S 0.33,
而实照立面木构是 **H 13–28°、S 0.11–0.19**。
本系统的面只要与既有木构同调即可;单独把某几片压到实照的绝对值,
会在一堆暖褐里显得发灰发假。要动就得动全塔的色彩分级,那是另一件事。

### 8.4 实照取色的锚点

| 部位 | 实照值 | 来源 |
|---|---|---|
| 立面木构 | H 13–28°、S 0.11–0.19、L 0.25–0.38 | 2025 实照 / 2017 正射 |
| 一层红墙 | H 6–8°、S 0.31–0.36、L 0.31–0.43(背光 `#6a3c36` / 受光 `#9b5448`) | 2025 实照 |
| 三、四层木构 | `#72564e`(H 13°、S 0.19、L 0.38) | 2017 正射 |

### 8.5 出图机位要挑得见改动的

`?view=elev` 正对南面(面 0),而南面当心间是板门、两代同在,
被封死的斜向面(1/3/5/7)全落在画面两侧的极度透视压缩带里,一两个像素宽。
**改斜向面就必须补 `?view=se` 一张。**

深链接:`?era=ancient|modern`,配 `&snap=1` 出对照静帧;`G` 键切换。
`era` 与 `mode` 正交,巡航、逐层、分解、剖透视里都能随时切。

### 8.6 几何还是材质:先量标高

「墙比柱矮了一截」曾被当成几何缺失,量完发现那 0.51 m 是阑额实实在在占着的,
缺的是**色系**——阑额还挂着裸木族,立面上「红柱→红余壁→灰褐一条→斗栱」在梁下断开。

> **先量标高再决定改几何还是改材质。**

### 8.7 内槽 / 外槽 / 副阶的夹取

`buildLintelRing` 给三处用的是同一个 `partKey`,只能按到轴线的水平距离夹:

```
下界 = (内槽R + 外槽R) / 2      上界 = (外槽R + 副阶R) / 2
```

内槽在室内不属立面;**副阶更要排除**——实照上副阶柱是终年受晒的灰褐裸木,
它那圈枋跟着上红就会出现「灰柱顶着红枋」。
实测:外槽 240 件上红,内槽 80、副阶 48 不动。

## 九、性能约束

改任何一处之前先确认不会破这三条:

| 约束 | 现状 | 怎么守住的 |
|---|---|---|
| 铺作绘制批次不增 | 45 个 InstancedMesh,着色前后一样 | 逐朵色差走 `setColorAt`,不拆材质、不拆网格 |
| 贴图张数受控 | 版壁 6 种面只有 2 张贴图;勾阑格扇 9 种面只有 3 张 | `Material.clone()` **共享贴图**,只换 `color` 乘子 |
| 遮罩副本只在过渡时双份 | 静止态只画一片 | 副本不透明时关本体,古貌时关副本 |

淡化写法:**只在 `transparent` 真的翻转时才置 `needsUpdate`**。
`opacity` 与 `depthWrite` 是 uniform 与状态位,改了不必重编译;
每帧都置 `needsUpdate` 会逐帧重编译着色器,足以把 2 秒的过渡拖成幻灯片。
