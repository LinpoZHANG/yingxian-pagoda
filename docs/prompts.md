## 阶段 3 完成记录(2026-09-02):建造(Claude Code)

- **先立骨架再上肉**:严格按「八角几何 → 台基柱网 →(截图看比例)→ 梁枋墙身
  → 屋檐 → 斗拱文法 → 塔刹 → 场景 → 交互 → HUD」推进;
  每完成一段就渲染一张正立面比对,而不是全部写完再看 —— 比例错误发现得越早,
  返工面越小(翼角起翘的三轮调值即是在这个循环里收敛的)。

- **求解层先于建造层**:把三组彼此独立的实测锚点(柱环半径 / 檐口标高宽度 /
  平座标高宽度)先解算成一份逐层放样表(assembly/plan.js),再让构件去读它。
  好处是「暗层柱高」这类无实测值的量由上下锚点**反解**得出,而不是另拍一个数;
  也使各层铺作顶与实测檐口的残差(≤0.55 m)一次性暴露、可评估、可记录。

- **给 AI 造一把秒级的尺**:headless Chrome 软件渲染一张图要一两分钟,
  不足以支撑迭代。改为在 Node 里桩掉 Canvas/DOM,只跑几何生成路径,
  100 ms 内输出「构件数 / 三角形数 / 全塔包围盒 / 最外构件是谁 / 屋面法线均值」。
  普拍枋朝向错误(沿半径伸出 21.6 m)、屋面法线反向、几何属性集不一致导致合并失败
  —— 三个缺陷都是这把尺量出来的,截图只用于最终的审美判断。

- **让规则涌现,而不是逐个建模**:斗拱不写五十种,只写一套《法式》文法
  (栌斗坐底 → 每跳升一足材、出三十分 → 计心置横栱、偷心跳空过 →
  外侧若干跳改昂 → 转角三向并置、斜出跳按 1/cos22.5° 加长),
  再由 PUZUO 等级表驱动。改一个 `tiao` 值,全塔该层四十朵斗拱一起变。

- **对 AI 的自我怀疑保持警惕**:第一轮渲染中因法线反向看到「木色屋顶」,
  一度要去改瓦材质;正确做法是先证伪(在 Node 里量法线方向),
  再动手。同类教训:「起翘过缓」的误判导致参数被上调 60%,法线修正后又调回。
  凡「看起来不对」,先问「是不是量错了」。

- **[估] 值的去向必须当场写清**:data/ 里每个 [估] 都在注释里写明调优依据与去向,
  调整过程逐条记入 docs/adjustments.md,交付时可完整回溯「哪些是测的、
  哪些是推的、哪些是猜的」。

## 第13轮追加:自检脚本同受「单一数据源」宪法管辖

第12轮改了翼角冲出的常数,断言一/二当场吐出 41272 个假「越面点」。
根因不在模型,在**探针**:`tileYAt()` 自己把翼角冲出重算了一遍
(`ROOF.cornerOut * P.scale`),还自带一份 `scale = eaveR / 15.65` 的魔法数。
它是一条与生成路径并行的第二放样线 —— 正是 `roof.js` 抬头警告过的那种。

教训写进方法要点:

- **架构约定第 1 条(参数唯一)管的不只是构件文件,也管自检脚本。**
  探针必须从被检对象身上取参(`P.cornerOut` / `P.cornerZone`),
  不许自己复现一遍生成逻辑;复现出来的那份,迟早会和真身分叉。
- **判据要从世界几何量,不要读名义数字。** 断言四第12轮改为向上/向下投射实测
  上下件表面之后,才量出「柱头戳穿普拍枋 0.026 m」这类旧判据结构性看不见的缺陷。
- **一条断言若从未报过错,先怀疑它的判据。** 旧断言四只查悬空一侧,
  三处埋入缺陷全部显示 ✔,而且是自己写的豁免注释把它们放过去的。

同源教训还有一条(第13轮 §一):两个「硬锚」若来自同一读数,
互推只会回到自己。用它们派生第三个量之前,先乘一下看是不是同一个数。

## 第15轮追加:让缺陷「可被断言抓住」是设计目标之一

翼角起翘从「皮肤上的场」改成「生头木垫出来、角梁传下去」,几何上其实只动了
一件事(消散函数的起点),但**验收能力**变了一个量级:

- 旧路线:起翘是 `surfacePoint()` 里的一行加法,没有上件也没有下件,
  断言四无从下手 —— 0.49 m 的悬空在自检里完全不可见;
- 新路线:「椽坐生头木」「角梁坐转角铺作」「飞子叠椽」三类节点各有明确的上下件,
  逐件量到 0.000 m,而且第一版做错的两处(生头木摆在理想八角线上、
  弦-弧亏欠共用一个值)都是被这三条断言当场抓出来的。

方法要点:**设计构件时同时设计它的判据**。一个没有判据的构件,
等于把它的正确性寄托在渲染截图和肉眼上;而肉眼这一轮看不见的东西,
下一轮换个机位就会变成用户圈红的那个框。

## 第16轮追加:把一个方向上的结论平移到另一个方向,是典型的错法

第15轮我从「檐椽段是一根直椽、起翘幅值应在段内恒定」推出了**沿坡向**的正确修正
(衰减不该跨过檐椽段)。第16轮我把同一个「平滑」直觉套到了**沿面宽向**,
主张起坡点该更早、升得更缓 —— 版18 立面一看即知不是那样:
完成面檐口以平直为绝对主调,只在最后一两个椽档里一挑到位。

两个方向的物理完全不同:沿坡向是**一根构件的走向**(直椽必须直),
沿面宽向是**一排构件的高度分布**(由生头木的楔形决定,想多陡有多陡)。
把前者的结论平移到后者,没有任何依据,而我当时没有回图纸复核。

由此补一条选图规则(已写入 reference/README.md):
**形态以立面/照片为准;剖面管构造,平面管布置。**
凡涉及看得见的形,先翻立面与实物照片,再谈推理。
