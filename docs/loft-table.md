# 全塔标高总表(loft table)

> **本表是竖向的唯一权威。** 今后任何竖向改动,必须**先改本表、再改代码**;
> 构件不得自带独立标高源 —— 一切竖向定位都应能在这里找到出处。
>
> **【宪法条文,第13轮批准】构件要用的标高,先在表里加行,不许就地凑。**
> 表里没有那一行,就说明这个标高还没有被裁定过;此时正确的动作是**加行**,
> 而不是在构件里就近拿一个数拼出来。历史教训:墙下皮表里无行 → 构件就近取了
> 「柱脚 + 柱础露明高」→ 整道墙悬空 0.136 m(见 adjustments.md §一);
> 普拍枋标高表里无行 → 一圈平枋另取数字 → 与生起起伏的柱头脱节(§二)。
> 由 `src/assembly/plan.js` 的 `buildLoftTable()` 生成,自检脚本每次运行打印。
>

>
> 竖向体系现状(截至第10轮):
> 1. **链驱动** —— 明层柱头、暗层柱头、副阶柱头的绝对标高取自版3 十四段全链;
> 2. **face 语义** —— VERTICAL.eaves.eaveY 视作面心檐口(两种语义跑拟合,face 越带少);
> 3. **铺作裁定** —— 铺作坐于「柱头 + 普拍枋」之上,总高由材分推算,内外槽同一放样行;
> 4. 版17 柱高 2.86、剪影平座标高 均降为**交叉校验**,不再驱动几何。
> 5. (第12轮)**铺作总高不可压**:层间净空恒为 0,竖向缺口不得摊到铺作步进上,
>    只能立案;现存缺口的证据指向径向账目(檐出偏小),见 adjustments.md §一。
